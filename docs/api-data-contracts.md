## Stored fields, nullability, and transformations

Every listed Parquet column is physically nullable according to its Arrow schema. In the inspected data, all 17 incident columns had zero null values. Detection `username` was null in 111/258 rows; all other 19 detection columns had zero nulls in this sample. Zero observed nulls are not a guarantee for future input: optional source fields can be absent, and the Parquet schemas permit nulls.

| Stored dataset/field(s) | Stored type | Public JSON representation | Nullability and provenance |
|---|---|---|---|
| Detection `detection_id`, `rule_id`, `rule_name`, `category`, `severity`, `description`, `confidence` | UTF-8 string | String | Stored strings; generated by detection pipeline. API requires these fields but should reject/flag nulls as data-integrity failures. |
| Detection `srcip`, `dstip`, `username`, `host` | UTF-8 string | String or `null` | Source-derived; `username` is absent in 111 actual sample rows. `host` may be sourced from `devname` or `hostname`. |
| Detection `eventtime`, `date`, `time`, `tz` | UTF-8 string | String or `null` | Preserved timestamp text. Do not parse, round, normalize timezone, or convert to JSON number. |
| Detection `source_file`, `line_number` | UTF-8 string, Int64 | String or `null`; integer or `null` | Evidence locator from the input. File paths may need redaction per deployment policy. |
| Detection `evidence` | UTF-8 string containing JSON object | Object or `null` | Decode JSON on response; stored object values remain original strings where sourced from parser fields. |
| Detection `matched_conditions` | UTF-8 string containing JSON array | Array of condition objects or `null` | Decode JSON. Each item contains `field` and `op`; `value` is optional (the current `exists` rule omits it) and, when present, may be a JSON scalar/array. |
| Detection `mitre_techniques` | UTF-8 string containing JSON string array | String array or `null` | Decode JSON. The inspected sample contains only `T1110`; no technique names/tactics are stored. |
| Incident `incident_id`, `title`, `description`, `severity`, `confidence`, `first_observed`, `last_observed`, `status` | UTF-8 strings | String; observation bounds may be `null` | Stored summary values. IDs and prose are produced by correlation. Observation text remains exact. |
| Incident `detection_count`, `unique_source_events` | Int64 | Integer | Stored computed values from correlation; expected non-null by API contract. |
| Incident `related_srcips`, `related_dstips`, `related_usernames`, `related_hosts`, `detection_ids`, `correlation_reasons` | UTF-8 strings containing JSON arrays | Corresponding JSON arrays or `null` | Decode JSON. `detection_ids` is a stored summary copy; relationship Parquet is authoritative for lookup. |
| Incident `evidence_refs` | UTF-8 string containing JSON array of objects | Array of evidence-reference objects or `null` | Decode JSON; objects contain `source_file` and `line_number`. |
| `incident_detections.incident_id`, `.detection_id` | UTF-8 strings | Not returned directly by default | Stored relation is the authoritative join key between an incident and detections. |
| Graph node `id`, `type`, `value` | JSON strings | Strings | Copied from `graph.json`; node types observed: `ip`, `user`, `host`, `technique`, `detection`, `incident`. |
| Graph edge `source`, `target`, `rel` | JSON strings | Strings | Copied from graph; both endpoint IDs must refer to returned nodes. |
| Graph edge `evidence` | JSON string or null | String or `null` | Semantics depend on `rel`: for source-observed edges it identifies the source record; for `RELATED_TO_INCIDENT` it is a relationship reference; on `MAPPED_TO_TECHNIQUE` it is source-record provenance only, not proof of the technique mapping. |
| Graph edge `line` | JSON integer or null | Integer or `null` | Source input line for evidence-backed edges, including technique mappings; it locates the detection's record and does not substantiate the mapping. `RELATED_TO_INCIDENT` has `null`. |
| Graph edge `observed` | JSON boolean | Boolean | Preserve exactly. `false` denotes derived relationships, including `MAPPED_TO_TECHNIQUE` and `RELATED_TO_INCIDENT`, in current graph output. |

Graph provenance has three distinct meanings: **source evidence** locates the input record behind an observed detection relationship; **relationship references** identify the detection/incident pair for `RELATED_TO_INCIDENT`; **analytical mapping provenance** would identify the rule or mapping catalog/version and rationale for `MAPPED_TO_TECHNIQUE`. The current graph carries source-record provenance on technique edges but does not store analytical mapping provenance explicitly. Source path/line on `MAPPED_TO_TECHNIQUE` does not prove the technique mapping; never present it as proof that the mapping is correct.

### Computed at request time

`total_detections`, `total_incidents`, severity/category counts, and `unassigned_detections` are aggregates over the configured snapshot. `pagination.total` is the count before pagination; `next_cursor` is a generated opaque continuation token. Technique `detection_count` is an aggregate over decoded technique arrays. Timeline items are projections of linked detection rows, not new event records. Graph membership and edge selection are computed by the graph filtering algorithm. These values are not stored as API response rows.

## Verified facts versus proposed contract

**Verified:** the schemas and serialized forms above come from engine source and actual Parquet/graph inspection. Current sample aggregates are 258 detections, 181 incidents, 258 relationship rows, severity/category counts shown in [api-design.md](./api-design.md), and `T1110` on 147 detections. Detection username is null in 111/258 sample rows. All inspected incident columns were populated.

**Proposed:** API envelopes, requiredness, parameter validation, page/cursor model, health store state, summary field names, timeline projection, graph response metadata, error codes, and limits. These must be agreed before implementation. The API contract is stricter than physical Arrow nullability for generated IDs and required descriptive fields; encountering nulls in those fields should produce a data-integrity error, not a silent fallback.
